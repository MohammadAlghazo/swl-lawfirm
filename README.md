# سمو الحكمة للمحاماة

موقع عربي مبني على Next.js 15.5.28 وReact 18، مع لوحة إدارة للمقالات ورسائل التواصل. توثيق الهوية وسلوك الواجهات في DESIGN.md.

## التشغيل

استخدم Node.js 20.9 أو أحدث. ثبت الاعتماديات عبر `npm ci`، ثم جهز متغيرات البيئة في ملف `.env` المحلي:

- `DATABASE_URL`: رابط قاعدة البيانات الحالية المتوافقة مع مخطط Prisma في `prisma/schema.prisma`.
- `JWT_SECRET`: قيمة عشوائية خاصة بطول ٣٢ حرفاً على الأقل. يجب ضبطها في بيئة الإنتاج؛ لا تستخدم قيمة موجودة في الكود أو تنشرها في المستودع.
- `RESEND_API_KEY`: اختياري لإشعارات البريد. تحفظ الرسائل في قاعدة البيانات حتى إن تعذر إرسال الإشعار.

شغل `npm run dev` ثم افتح http://localhost:3000.

## التحقق

- `npm run typecheck`
- `npm run lint`
- `npm test` — اختبارات معالجة الرسائل باستخدام قاعدة بيانات وبريد محاكيين، دون إرسال خارجي.
- `npm run build`
- `npm start -- -p 3001`، ثم `npm run verify:site -- http://localhost:3001` لفحص الصفحات والبيانات الوصفية والحماية والمدخلات غير الصالحة، دون حفظ رسائل تجريبية.

لفحص إنتاج منفصل أثناء تشغيل التطوير، اضبط `NEXT_DIST_DIR=.next-verify` في أمرَي البناء والتشغيل. على PowerShell:

```powershell
$env:NEXT_DIST_DIR='.next-verify'
npm run build
npm start -- -p 3001
```

بناء الإنتاج يفحص الأنواع وESLint ولا يتجاوز أخطاءهما. التغييرات المحلية لا تنشر الموقع تلقائياً. عند النشر يجب توفير `JWT_SECRET` الخاص بالإنتاج عبر إعدادات الاستضافة.

صور الشركة الموجودة محلياً تستخدم next/image؛ صور المقالات الخارجية تبقى مباشرة في المتصفح مع بديل بصري عند الفشل. بيانات الفروع محفوظة كما وردت في المشروع، وروابط الخرائط تبحث باسم المكتب والعنوان؛ تحديد دبابيس دقيقة يحتاج رابطاً مؤكداً لكل فرع.
